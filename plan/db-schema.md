# ATS Skill — database schema spec (rebuild)

Source: `~/workspace/user/files/atsskill.sql` — MySQL 8 dump of
database `atsskill1` (phpMyAdmin 5.2.1, generated 2026-11-24).
Generated by `scripts/generate_migrations.py` — re-run it to
regenerate the migrations, seeders and this file. The source dump
is never modified. Table and column names are kept **exactly** as
in the old database; nothing is renamed.

- Old tables in the dump: **112**
- Total columns across old tables: **903**
- Migration files generated: **118** (112 old tables + 6 new media pivots)
- Seeder files: 5 (`RolePermissionSeeder`, `SettingSeeder`, `LanguageSeeder`, `EmailTemplateSeeder`, `DatabaseSeeder`)
- Declared foreign keys in the dump: **24** (see below)

- Permissions: **105**, roles: **2**
- Setting keys: **55**, email templates in dump: **2**, languages: **2**

## Discrepancies vs the brief (verified against the dump)

- **Settings: 55 keys, not 88.** The `settings` INSERT holds 55
  rows. The `SettingSeeder` seeds all 55 (key names only for
  credential-like keys — see Security below).
- **Email templates: 2, not 17.** Only `password_reset` and
  `contact_mail` exist in the dump. The other 15 templates the
  brief expected are not in this dump; they must be recreated
  from the old mail views if still needed.
- **Foreign keys: 24 declared, not ~20.** Only 24 of the
  hundreds of `*_id` columns have a declared FK constraint; the
  rest are code-enforced in the old app and stay that way here
  (plain `unsignedBigInteger` columns, no constraint).
- **`media` already exists** in the dump (`id, name, src, type,
  extension, deleted_at, created_at, updated_at`) — it is kept
  as-is and the 6 new pivot tables reference it.
- **`migrations` table:** Laravel's migrator owns it. Its
  migration is generated with a `Schema::hasTable()` guard so a
  fresh `php artisan migrate` does not fail on it.
- **Framework tables duplicated:** `jobs`, `failed_jobs`,
  `password_reset_tokens`, `personal_access_tokens` are also
  created by stock Laravel 13 migrations. Keep either the stock
  ones or these generated ones, not both — the shapes match the
  old dump (note `jobs.created_at` is an `int`, not a timestamp,
  and `failed_jobs.failed_at` defaults to `CURRENT_TIMESTAMP`).

## Security — what is NOT in the seeders

The dump contains real-looking credentials (payment-gateway keys,
a Mailtrap SMTP password, a reCAPTCHA secret, a UddoktaPay API
key, Stripe test keys) and a bank account number inside
`basic_payments.bank_information`, plus hashed user/admin
passwords. **None of those values are copied into any generated
file.** `SettingSeeder` seeds credential-like keys as
`env('KEY_NAME', '')` placeholders; no users or admins are
seeded at all. Set real values in `.env` only.

(e.g. `courses.thumbnail`, `users.image`, `brands.image`). The
rebuild adds a central `media` table (already in the dump) plus
one pivot per entity. Each pivot has: `id`, `<entity>_id`
`unsignedBigInteger`, `media_id` `unsignedBigInteger`,
`is_primary` `boolean` default `false`, `order`
`unsignedInteger` default `0`, `timestamps()`, a unique
`[<entity>_id, media_id]` pair, and `ON DELETE CASCADE` FKs to
both sides.

- **`course_media`** — `course_id` → `courses`, `media_id` → `media`
- **`blog_media`** — `blog_id` → `blogs`, `media_id` → `media`
- **`testimonial_media`** — `testimonial_id` → `testimonials`, `media_id` → `media`
- **`brand_media`** — `brand_id` → `brands`, `media_id` → `media`
- **`team_member_media`** — `team_member_id` → `team_members`, `media_id` → `media`
- **`instructor_media`** — `instructor_id` → `instructors`, `media_id` → `media`

## Edge cases / things that did not map cleanly

- **No exotic types.** Every column maps with the table above;
  there are no `json`, `mediumtext`, `datetime`, `time`, `char`,
  `set` or generated columns in the dump.
- **`landing_pages` has no `ENGINE=` clause** (ends `) ;`).
  Parsed line-by-line; nothing lost.
- **Binary collation longtexts:** `featured_instructors.instructor_ids`,
  `landing_pages.content`, `quiz_results.result` are `longtext
  CHARACTER SET utf8mb4 COLLATE utf8mb4_bin`. Mapped to plain
  `longText()`; Laravel's default collation applies. If byte-wise
  comparison matters for those three columns, add the collation
  back with `->collation('utf8mb4_bin')`.
- **`order` and `key` as column names** (`course_categories.order`,
  `settings.key`, `payment_gateways.key`, …) are kept verbatim;
  they are fine as string arguments in the Blueprint calls.
- **`users.status` / `users.is_banned` are `varchar(255)`**, not
  enums/booleans — kept as `string` with the old defaults
  (`'active'` / `'no'`). Same for `instructors.status`, which is
  a nullable `tinyint(1)` default `'1'` → nullable boolean.
- **Spatie pivot tables** (`model_has_permissions`,
  `model_has_roles`, `role_has_permissions`) use composite
  primary keys, reproduced with `$table->primary([...])`.
- **`password_reset_tokens`** has PK `email` (no `id`), reproduced
  as `string('email')->primary()` via `$table->primary(['email'])`.
- **Duplicate `configurations` rows:** `setup_complete` /
  `setup_stage` each appear twice (ids 1–2 and 3–4, different
  values). Not seeded; the installer flow should own these.
- **`basic_payments` / `payment_gateways` values are not seeded
  at all** — they hold gateway credentials. Only their key names
  are documented here via the `settings` list pattern; gateway
  keys present in the dump: `razorpay_*`, `flutterwave_*`,
  `paystack_*`, `mollie_*`, `instamojo_*`, `uddoktapay_*`,
  `stripe_*`, `paypal_*`, `bank_*` (names only, no values).
